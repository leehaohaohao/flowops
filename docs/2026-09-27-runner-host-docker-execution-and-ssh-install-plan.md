# 子节点 SSH 管理与宿主机部署路线图

> 状态：计划拆分完成，以下四阶段均待实施。本文件只记录顺序；每阶段以对应计划表的范围和验收条件为准。

目前在 FlowOps 创建普通“子节点项目”再部署，是一次手工联调方式。正式流程改为在**节点管理**中登记节点、配置 SSH 目标、分发执行器包并选择启动方式。SSH 用于安装和管理子节点；正常业务部署仍由已连接的子节点执行。

| 顺序 | 独立计划表 | 本阶段结束时可做什么 | 不包含 |
| --- | --- | --- | --- |
| 1 | [SSH 连接验证](2026-09-27-node-ssh-connection-plan.md) | 在节点管理页配置目标并由主节点验证 SSH 登录、远端命令与 SFTP 通道 | 不传包、不启动子节点、不改协议 |
| 2 | [执行器包分发](2026-09-27-runner-package-distribution-plan.md) | 上传有清单与校验和的执行器发布包，并经 SSH 安全分发到目标机 | 不启动/更新进程、不创建业务容器 |
| 3 | [双模式启动与节点操作](2026-09-27-runner-start-and-node-operations-plan.md) | 在节点管理页选 Docker 容器或宿主机原生方式安装、启动、停止、重启执行器 | 不把子节点包装成普通服务项目 |
| 4 | [宿主机 Docker 部署闭环](2026-09-27-runner-host-docker-deployment-plan.md) | 两种执行器模式都能在目标宿主机创建/查询/停止业务容器，主节点识别可部署状态 | 不使用 Docker-in-Docker，不通过 SSH 执行每个业务任务 |

阶段 1 是当前下一项工作。阶段 2 依赖阶段 1 的连接契约；阶段 3 依赖阶段 2 的发布包；阶段 4 依赖阶段 3 的真实运行环境。任何阶段均不能用日期或代码提交代替真实验收。
